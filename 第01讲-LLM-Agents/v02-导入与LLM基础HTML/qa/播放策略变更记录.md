# 2026-10-19 播放策略调整

教师最新要求：普通页面进入时完整显示；只有特别必要的机制变化保留分步。该要求替代原先广泛使用逐项揭示的展示方式。

## 发现的问题

- 原播放器直接采用每个 renderer 的 `steps`，把标题、条目、图形与小结的逐项揭示全部当作课堂步骤。
- 不能简单把所有页面强制设为原末态：原稿第25、77、78、96、97、101、103、108、123页有随时间改变的正文、数值、返回内容或箭头，前态含有末态无法替代的信息。
- 原打印只保留末态，会遗漏文件已修改但输入尚未更新等必要的中间状态。

## 已修改

- 普通页只保留一个播放状态，按原末态渲染并完整展示所有 `data-reveal` 内容，控制栏显示“整页显示”。
- 保留机制使用显式 `source_steps`，分开记录播放步骤与原 renderer 状态。此类页面仍按原状态控制信息出现时点，按钮不会自动推进。
- Prompting 和 Agents 部分的9个例外及理由集中记录在 `src/playback-policy.json`，按稳定的 `authoring_page` 原稿编号匹配。新页码为20、72、73、91、92、96、98、103、118。第一部分第4–14页全部整页显示；第8页内部查看生成轨迹的按钮不增加播放器步骤。
- 删除机制页中单纯揭示背景的多余点击。例如新第20页直接呈现错误方向的完整例子；下一步显示核算修正。
- 普通页下一步直接翻页；旧网址中过大的步骤号按本页新步骤数收敛。页码、状态数、目录跳转和回退均使用同一份播放映射。
- 打印保留各页选定的全部机制状态，普通页仍为一张；机制打印页标明“演示 x/y”。
- 构建脚本统一输出播放信息、步骤总数、打印张数和 `qa/playback-policy-record.json`，避免播放器与清单各算一套。
- 第一部分由原16页改为11页，后章页码统一减5，全讲共129页。后章模块原稿编号和 renderer 保持稳定，构建时映射 `page`、材料和文件入口；目录按原稿组别查找新页码。来源定位文字保留原资料的页码含义。
- 本地预览曾因浏览器复用旧脚本而显示旧页数。构建在所有数据写完后，为 `index.html` 的28个本地JS/CSS引用添加文件SHA256前12位版本号；再次构建时剥离旧query读取原文件。图片、字体和资料阅读页链接不改。
- 页面内按钮、链接、输入框等控件的双击不触发图解放大，避免生成轨迹按钮连点误开弹窗。

## 实际验证范围

`qa/check-playback-policy.cjs` 在 Node VM 中执行播放器，使用最小 DOM 检查播放逻辑。验证了完整前进/回退序列、原状态映射、普通页完整显示、机制 reveal、打印状态对应、旧 hash 边界，以及跨页和返回页面。

新第一部分合入后已重新运行：129页、144个播放器状态，12项逻辑检查通过，包括新目录每页恰好一次、6类控件各5次双击排除、全部28个JS/CSS引用hash一致。带已有query的再次构建也正常完成。结果保存在 `qa/playback-policy-checks.json`，资源版本保存于 `qa/asset-versions.json`。

这项记录是代码运行层面的逻辑验证，不是浏览器视觉检查，不代替教师查看或实际浏览器操作。第8页页内按钮和必要机制的初态、中态、末态仍需由主任务在浏览器核对。
