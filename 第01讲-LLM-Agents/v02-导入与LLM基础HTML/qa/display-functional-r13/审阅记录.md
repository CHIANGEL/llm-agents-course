## 实际发现并修复的问题

### R13-01：关闭放大窗口后，正文丢失窗口中的操作状态（已修复）

- 复现：第100页正文选择“磁盘已更新” → 放大 → 选择“再次读取” → 关闭。正文错误地回到“磁盘已更新”。
- 原因：放大窗口使用正文副本，关闭时未将更新后的控件与内容带回正文。
- 修改：`src/player.js` 的 `closeModal()` 在关闭图解弹窗时，将当前放大内容的节点放回正文，保留选择与事件绑定。
- 复查：第100页复走原路径，正文保持“再次读取”；另外复测第6、8、68、92、94、96、97、99、108、113、114、115、117、118、119、139页的放大交互返回。14项文本对照记录全部一致，第6页额外核对温度与top-k的实际控件值，第8页核对Token位置。
- 证据：`widgets/100-zoom-reread.png`、`widgets/100-after-zoom-before-fix.png`、`widgets/100-after-zoom-fixed.png`、`zoom-roundtrip.json`、`deliverable-fixed-state.png`。

### R13-02：页码越界输入被浏览器校验拦截，输入与正文不一致（已修复）

- 复现：第100页输入176并回车，输入框停在176，正文仍为100；0和小数有同类问题。
- 原因：浏览器原生表单校验先于已有的页码归位逻辑。
- 修改：`index.html` 的页码表单增加 `novalidate`，继续使用既有整数与边界处理。
- 复查：0 → 1；176 → 175；空值 → 保持当前175；1.5 → 1；100 → 100。输入框与正文页码一致，未误触发其他快捷键。
- 证据：`page-input-before.png`、`page-input-fixed.png`、`player-controls.json`。

备份在 `before/`。入口中的播放器缓存版本和 `qa/asset-versions.json` 已同步。最终核对44项入口资源哈希全部匹配，player.js语法检查通过；记录在 `final-static-check.json`。没有修改页面内容JSON、配图、标题、正文或讲者备注。
