## 六个子模块的素材分工与总分总

| 子模块 | PDF对应 | 总览关系 | 展开对象 | 总结原结构 |
| --- | --- | --- | --- | --- |
| 任务交代 | 原课四件套为主，PDF第1页补充提供背景与原始材料 | 使用者/受众、目标、材料、约束 → 交付 | 原课经营分析任务单、示例格式、必要条件 | 输入让模型明确做什么、依据什么、交付什么 |
| 澄清关键问题 | PDF第2–3页苏格拉底式提问 | 已知信息 → 关键缺口 → 有针对性的一问 → 新问题 | 原课访谈的事实/解释/目标；原课汇报提纲用途的追问 | 只问改变结论的问题；信息足够就继续 |
| 核查事实与结论 | PDF第6–7页事实核查 | 待核查说法 → 材料与计算 → 推理与范围 → 调整结论 | 原课12/20访谈与扩店经营材料 | 事实有依据，推理连得上，结论范围相符 |
| 比较选择 | PDF第9–10页双向钢人论证 | 同一目标与约束 → 两方理由与条件 → 关键分歧 → 改变选择的变量 | 先验证实际试用/准备收费推广 | 选择取决于条件与新信息 |
| 验证关键假设 | PDF第10页最小实验 | 关键假设 → 小范围行动 → 观察指标 → 继续/调整/停止 | 原型、试用记录、判定点 | 行动要产生可用于下一步判断的新信息 |
| 反馈、修改与检查 | 教师心得与原课为主；PDF不提供这一专门模板 | 结果 → 具体反馈 → 修改 → 再检查 | review/critique/improve；润色；代表性材料 | 保留目标，明确改动，用相同要求检查 |

PDF“学习”中双层解释、反向拆解、横纵分析不是本次六模块主线。隐藏天赋、人生设计不进入本讲。不要把作者“我自己用了很久”“我在公募基金工作时”等经验变成教师亲历。

## 1. 澄清关键问题（PDF第2–3页）

### 上屏短句

- 先分清：发生了什么、怎样解释、希望实现什么。
- 每次问一个问题，根据回答决定下一问。
- 只问可能改变结论的问题，信息足够就停止。
- 澄清后留下：已知事实、关键假设、关键变量和一个具体的新问题。

原文完整分类是可验证事实、对事实的解释、价值判断、希望实现的目标。屏幕三列“事实/解释/目标”可作为原课访谈例子的取舍；价值判断可在完整模板保留。

### 短Prompt

> 先不要给建议。请区分已知事实、我的解释和目标，每次只问一个可能改变结论的问题；信息足够时停止。

### 完整Prompt素材（整理稿；可放材料阅读）

```text
我的困惑是：【尽量具体地描述发生了什么、你怎么理解，以及你卡在哪里】。
先不要给建议。请通过最多6个问题，帮我找到真正值得回答的问题。

请遵守这些规则：
1. 每次只问一个问题，根据我的回答决定下一问，不要提前给我一整套问卷。
2. 优先区分我说的是可验证的事实、对事实的解释、价值判断，还是我希望实现的目标。
3. 检查关键词是否含糊、我默认了哪些前提、证据来自哪里、有没有相反解释。
4. 每次提问前，用一句话说明上一条回答让你更新了什么判断。
5. 只问可能改变结论的问题。信息足够时立刻停止，不必凑满6个。

问诊结束后，请整理出：
1. 我最开始问的问题；
2. 我真正想解决的问题；
3. 已经确认的事实；
4. 仍未验证的假设；
5. 最可能改变结论的关键变量；
6. 一个准确、具体、可以继续行动的新问题。

等我确认这个新问题以后，再给出你的判断、理由和下一步行动。
```

### 配图与分步

使用真实原课访谈摘录页，不再单列三个抽象方框。第一步原句“20位受访者中12位愿意试用”；第二步将“12位”连到事实，将“大家会买”连到待验证解释；第三步把追问落到“是否调查了付费意愿”；第四步回到“事实→缺口→问题”，归纳信息增加在哪里。若用原课汇报提纲用途例，则显示对话内容和提纲版式变化，避免只有聊天气泡。

## 2. 核查事实与结论（PDF第6–7页）

### 上屏短句

- 把一句说法拆成事实、推论和价值判断。
- 事实核对来源、样本、时间和完整上下文。
- 再看这些事实能否推出结论，结论在哪些条件下成立。
- 将判断连回支持它的原文、数据和计算。

五种核查状态原文为“已证实”“基本成立，但需要收窄”“存在争议”“证据不足”“明显错误”。它们属于核查的教学实质，可保留；不要因去掉防御性说明而删除“证据不足”等核查结果。

### 短Prompt

> 请把这段话拆成事实、推论和价值判断，逐条对应材料；检查事实能否推出结论，并写清适用范围。

### 完整Prompt素材（原文可见内容整理）

```text
我要核查的说法是：【粘贴观点、结论、数据或方案】。

请先把它拆成：
1. 可以被外部验证的事实；
2. 从事实推出的结论；
3. 其中包含的价值判断。

对于事实部分，请联网核查来源、样本、时间和完整上下文，并标记为：
1. 已证实；
2. 基本成立，但需要收窄；
3. 存在争议；
4. 证据不足；
5. 明显错误。

在假设相关事实成立的情况下，继续检查：
1. 这些事实能否推出当前结论；
2. 是否藏着未经验证的假设；
3. 是否混淆相关性和因果关系；
4. 是否遗漏了其他解释或关键信息；
5. 结论在什么条件下成立或失效。

最后请输出：
1. 哪些事实可信，哪些需要修正；
2. 推理链中最关键的漏洞；
3. 补强后的最合理版本；
4. 我目前可以相信到什么程度。
```

材料阅读可保留原文模板中的“联网核查”，页内演示用已有经营/访谈材料时，以“逐条对应材料”为动作。不要给页面制造一次联网查询的工具回执。

### 配图与分步

左侧访谈原件摘录与20人图，右侧核对记录三行“12位愿意试用—访谈原句”“60%—12÷20”“愿意付费—需要付费意愿资料”。通过逐行连线体现动作；最后回到“材料—计算—范围”三项。另一页原课经营材料中“新增3家门店，推广投入和管理人员增加”与三条推断并排，可支持扩店及费用增加；各门店盈亏/次年利润另需相应数据。不要给没有来源的公司编结果。

## 3. 双向钢人论证（PDF第9–10页）

### 上屏短句

- 把两个方向都论证充分，再比较它们成立的条件。
- 同一维度比较理由、收益、风险与条件。
- 找出真正的分歧，以及最可能改变选择的变量。
- 用一个关键问题补齐决定性的缺口。

### 短Prompt

> 分别给出两个方向最有力的理由、适用条件、收益与风险；找出最可能改变结论的变量，只追问一个关键问题。

### 完整Prompt素材（整理稿；仅保留完整可读条目）

```text
我需要做的决定是：【写清问题、两个选项、目标和现实约束】。

先别急着回答，也别默认我已经把问题想清楚。请先做一次双向钢人论证：
1. 用最完整、有力的方式，重述我真正需要做出的选择。
2. 分别给出支持两个方向的最强理由、适用条件、最大收益、最大风险。
3. 找出双方真正的分歧、最可能改变结论的关键变量，以及还需要补充的信息。
4. 只问我一个最可能改变结论的问题。

等我回答以后，再给出明确判断、理由、适用条件和下一步行动。
```

### 配图与分步

两侧并排有形对象：试用原型与行为记录；产品交付页与报价页。中间是共同目标，底部共同的比较维度。不要用天平图暗示已经获得客观权重。先揭示两种行动，再每次揭示一侧“收益→成立条件”，最后把双方条件连接到关键变量，保持真正的关系图。

已有材料只有12/20的试用意愿。可以把“原型是否可用”“是否能承担推广投入”“需要先了解实际使用还是付费反应”作为选择相关条件；不要自行填入真实转化、利润或样本行为结果。

## 4. 最小验证（PDF第10页）

### 上屏短句

- 先选最可能改变决定的假设。
- 设计低成本、可逆、限定周期的行动。
- 行动前写清观察指标和继续、停止条件。
- 行动后获得的信息，应能帮助下一步判断。

### 短Prompt

> 选出最可能改变结论的一个假设，设计低成本、可逆的最小验证，写清投入、周期、观察指标和继续或停止条件。

### 完整Prompt素材（完整原文可见）

```text
我正在纠结的是：【填写你的选择或想法】。

请先找出这个决定背后最需要验证的3个假设，再选出最可能改变最终结论的那一个。

围绕这个假设，帮我设计一个低成本、可逆、能在【7天或你能接受的周期】内完成的最小实验。

请写清：
1. 具体要做什么；
2. 需要投入多少时间和资源；
3. 观察什么指标；
4. 什么结果支持继续；
5. 什么结果提醒我停止；
6. 实验结束后能获得什么新信息。

最后告诉我，明天就能开始的第一个动作是什么。
```

### 配图与分步

可用原型视图、空白行为记录表、判断分叉。记录字段为“受邀、开始使用、放弃位置”；不填写行为次数。目标假设“愿意试用的人会开始使用”连接至观察字段，随后连接继续/调整/停止条件。画面标题可为“让行动带回判断所需的信息”。这属于教师演示的验证设计，不改成“现在请同学……”，不安排实际课堂执行。

- 第2页第2行末端挨近裁切边界；内容可读到“帮我找到真正值得回答的问题”，整理时略去“苏格拉底式问诊”以适合上屏，并保留最多6问的原文规则。

## 制作取舍

新增章首总览与章末总结使用同一“交代任务—补齐信息—形成方案—反馈检查”关系图。对应六方法时可用两级：交代任务→任务交代；补齐信息→澄清/核查；形成方案→比较/验证；反馈检查→反馈修改与检查。子模块用同一关系图开合，短节可在一页分步完成总分总。

PDF建议中的方法帮助组织输入和分析程序。课件结果若采用原课材料的手工对照，只描述展示的材料、关系、设计或批注，不写“模型运行后显示……”或伪造聊天时间戳。这一点在来源档案留记录即可，主画面无免责声明。
